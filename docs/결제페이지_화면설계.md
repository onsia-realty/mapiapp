## 1. 개요

### 1.1 구현 우선순위

**Phase 1 (런칭 필수, MVP)**:
1. 플랜 선택 — `/billing/plans`
2. 결제 입력 (Toss billing 위젯) — `/billing/checkout`
3. 결제 완료 — `/billing/success`
4. 마이페이지 - 구독 관리 — `/mypage/subscription`

**Phase 2 (런칭 후 1~2주)**:
5. 추가 등록 결제 (인라인) — 매물/구인구직 등록 화면 내부
6. 결제 내역 — `/mypage/payment-history`
7. 해지 플로우 (2-step + 사유 설문) — `/mypage/subscription/cancel`

### 1.2 용어집

| 용어 | 정의 |
|---|---|
| **Standard** | 유일한 유료 티어. 29,900원/월 (얼리버드 14,900원). |
| **얼리버드** | 선착순 100명. Standard 50% 가격(14,900원) 평생 락인 (연속 구독 유지 시). |
| **billingKey** | Toss Payments 정기결제용 카드 식별자. 우리 DB엔 reference만 저장. |
| **추가 등록** | Standard 할당량 초과 시 단건 결제로 등록하는 매물/구인구직. |
| **노출 보장** | 추가 등록 매물은 결제 시점부터 노출 기간 만료까지 노출 (구독 만료와 무관). |

### 1.3 디바이스 우선순위

- 모바일 90% / PC 10%
- **모바일 First** — PC는 모바일 디자인 확장
- 최소 터치 타겟 44px × 44px

**Toss billing 위젯 흐름**:
```typescript
// 1) 클라이언트
const tossPayments = await loadTossPayments(NEXT_PUBLIC_TOSS_CLIENT_KEY);
await tossPayments.requestBillingAuth("카드", {
  customerKey: session.user.id,
  successUrl: `${origin}/api/billing/register?plan=STANDARD`,
  failUrl: `${origin}/billing/plans?failed=true`,
});
```

**서버 처리** (`/api/billing/register`):
1. Toss로부터 받은 `authKey` → `POST /v1/billing/authorizations/issue`
2. 응답으로 `billingKey` 받음 → DB `Subscription.billingKey` 저장 (암호화)
3. 첫 결제 즉시 실행 (`/api/billing/charge`)
4. 성공 → `/billing/success` redirect

## 4. 데이터 모델 (Prisma 스키마 v2)

> 분양잡(`bunyang-job`) `Subscription` 모델 베이스 + 정기결제/얼리버드/추가등록 확장.

```prisma
// onsia-web/prisma/schema.prisma (신규 도입)

model User {
  id           String   @id @default(cuid())
  email        String?  @unique
  phone        String   @unique             // 게이밍 방지 (1인 1계정)
  name         String?
  certifiedRealtor Boolean @default(false)  // 자격증 인증 (admin 수동)
  certifiedRealtorAt DateTime?
  freeTierUsedAt DateTime?                  // 자격증 1개월 무료 사용 기록
  createdAt    DateTime @default(now())

  subscription      Subscription?
  boosterPurchases  BoosterPurchase[]
  paymentLogs       PaymentLog[]
}

model Subscription {
  id              String   @id @default(cuid())
  userId          String   @unique
  user            User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  tier            SubscriptionTier @default(FREE)   // FREE / STANDARD
  status          SubscriptionStatus @default(ACTIVE) // 신규 enum

  // Toss 정기결제
  paymentProvider PaymentProvider?           // TOSS
  billingKey      String?                    // Toss 카드 식별자
  customerKey     String?                    // Toss customerKey (= userId)

  // 얼리버드 락인
  earlybirdNumber Int?                       // 1~100, NULL이면 일반 가입자
  lockedPrice     Int?                       // 14900 (얼리버드만)
  priceLockExpiresAt DateTime?               // 해지 후 grace period 종료

  // 사용량 (매월 리셋)
  mapiUsed        Int @default(0)
  generalUsed     Int @default(0)
  jobBasicUsed    Int @default(0)

  // 기간
  currentPeriodStart DateTime
  currentPeriodEnd   DateTime                // billingKey로 자동 charge 트리거
  canceledAt         DateTime?

  // 결제 실패 재시도
  failedAttempts  Int @default(0)            // D+1, D+3, D+7 카운터
  nextRetryAt     DateTime?

  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

enum SubscriptionTier {
  FREE
  STANDARD
}

enum SubscriptionStatus {
  ACTIVE       // 정상 구독 중
  TRIAL        // 자격증 인증 1개월 무료
  PAST_DUE     // 결제 실패 재시도 중
  CANCELED     // 해지됨 (currentPeriodEnd까지 ACTIVE처럼 동작)
  EXPIRED      // 만료됨 (다운그레이드)
}

enum PaymentProvider {
  TOSS
}

// 추가 등록 (마피/일반/구인구직 단건 결제)
model BoosterPurchase {
  id           String   @id @default(cuid())
  userId       String
  user         User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  type         BoosterType
  targetId     String?              // 매물 ID 또는 구인구직 공고 ID

  amount       Int                  // 결제 금액
  exposureDays Int                  // 노출 일수 (30 또는 8)
  exposureExpiresAt DateTime        // 노출 만료일 (구독 만료와 무관)

  paymentKey   String               // Toss paymentKey
  paidAt       DateTime @default(now())

  createdAt    DateTime @default(now())
}

enum BoosterType {
  MAPI_LISTING                       // 9,900원 / 30일
  GENERAL_LISTING                    // 1,000원 / 30일
  JOB_REALTOR_BASIC                  // 20,000원 / 8일
  JOB_REALTOR_PREMIUM                // 50,000원 / 8일
  JOB_SALES_FREE                     // 무료 / 3일 (명함 인증 1건 한정)
  JOB_SALES_PREMIUM                  // 50,000원 / 8일
  JOB_SALES_MVP                      // 70,000원 / 8일
  JOB_SALES_HIGHLIGHT                // 100,000원 / 8일
  JOB_SALES_HEADLINE                 // 150,000원 / 8일
}

// 결제 audit log
model PaymentLog {
  id          String   @id @default(cuid())

  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  type        PaymentLogType

  errorMessage String?
```

### 5.1 핵심 라우트 명세

#### `GET /api/billing/plans-status`
```typescript

{

```

#### `GET /api/billing/register`
```typescript
// Toss billing 위젯에서 successUrl로 redirect 옴
// Query: authKey, customerKey
// 1. POST https://api.tosspayments.com/v1/billing/authorizations/issue
//    Body: { authKey, customerKey }
//    → billingKey 받음
// 2. Subscription.upsert: billingKey 저장, 얼리버드 번호 할당 (선착순)
// 3. POST /api/billing/charge (첫 결제 즉시 실행)
// 4. 성공 → /billing/success redirect
// 5. 실패 → /billing/plans?failed=true&message=... redirect
```

#### `POST /api/billing/charge`
```typescript
// Body: { userId } (cron 호출 시) or session 기반 (사용자 호출 시)
// 1. Subscription 조회 → billingKey, lockedPrice (또는 정상가)
// 2. POST https://api.tosspayments.com/v1/billing/{billingKey}
//    Body: { customerKey, amount, orderId: `MAPI_${userId}_${Date.now()}` }
// 3. 성공: 사용량 리셋, currentPeriodEnd 갱신, status = ACTIVE
// 4. 실패: failedAttempts++, nextRetryAt = D+1/D+3/D+7, status = PAST_DUE
//    3회 모두 실패 → status = EXPIRED, tier = FREE
// 5. PaymentLog 기록
```

#### `POST /api/billing/booster`
```typescript
// Body: { type: BoosterType, targetId?: string }
// 1. amount 결정 (BoosterType 별 고정)
// 2. 정기 구독자 (billingKey 보유):
//    POST /v1/billing/{billingKey} → 1초 결제
// 3. 비구독자: Toss 일반 결제창 (별도 흐름)
// 4. 성공: BoosterPurchase 생성, exposureExpiresAt = now + exposureDays
// 5. PaymentLog 기록
```

#### `POST /api/billing/webhook`
```typescript
// Toss webhook 수신 (https://docs.tosspayments.com/reference/using-api/webhook)
// 1. 서명 검증
// 2. 이벤트 타입에 따라 처리:
//    - PAYMENT_STATUS_CHANGED: 결제 상태 변경 (취소/환불 등)
// 3. PaymentLog 기록
```

## 6. Toss 정기결제 흐름

### 6.1 플로우

```
[사용자] → /billing/plans → "Standard 시작" 클릭
   ↓
[클라이언트] → tossPayments.requestBillingAuth()
   ↓
[Toss] → 카드 등록 위젯 → 성공 → successUrl로 redirect (authKey, customerKey)
   ↓
[서버 /api/billing/register]
   1. POST /v1/billing/authorizations/issue { authKey, customerKey }
      → billingKey 받음
   2. DB: Subscription { billingKey, status: ACTIVE, currentPeriodEnd: +30d }
   3. /api/billing/charge 호출 (첫 결제)
   ↓
[서버 /api/billing/charge]
   1. POST /v1/billing/{billingKey} { customerKey, amount: 14900, orderId }
   2. 성공 → 사용량 리셋, redirect /billing/success
   3. 실패 → redirect /billing/plans?failed=true
   ↓
[Cron 매일 실행]
   - currentPeriodEnd <= 오늘 인 ACTIVE 구독 조회
   - 각각 /api/billing/charge 호출
   - 실패 시 재시도 큐
```

### 6.2 결제 실패 재시도 정책

```
charge 실패 → failedAttempts = 1, nextRetryAt = +1일
   ↓ (D+1)
재시도 → 실패 → failedAttempts = 2, nextRetryAt = +2일
   ↓ (D+3)
재시도 → 실패 → failedAttempts = 3, nextRetryAt = +4일
   ↓ (D+7)
재시도 → 실패 → status = EXPIRED, tier = FREE
   ↓
사용자에게 알림 (이메일/카톡): "결제 실패로 Free 다운그레이드되었습니다. 카드 변경 후 재구독하세요."
```

> Toss billing API는 자동 재시도 미지원 → 우리 cron으로 명시적 처리.

### 6.3 Cron 환경 (Vercel Cron 또는 자체)

```
// vercel.json
{
  "crons": [
    { "path": "/api/cron/billing-charge", "schedule": "0 9 * * *" },     // 매일 09:00 KST
    { "path": "/api/cron/billing-retry", "schedule": "0 10 * * *" }      // 매일 10:00 KST
  ]
}
```

- `BoosterPurchase` 모델 + `/api/billing/booster` 라우트
- 결제 실패 재시도 cron
- 얼리버드 카운터 로직
- 자격증 인증 admin 페이지
- `PaymentLog` 모델 + audit 로직

### 7.4 작업량 추정

| 영역 | 분양잡 재사용 비율 | 신규 작성 |
|---|---|---|
| 결제 헬퍼 (lib) | 80% | 20% |
| 결제 API 라우트 | 50% | 50% (정기결제 변환) |
| Prisma 스키마 | 30% | 70% (v2 확장) |
| 화면 (UI) | 0% | 100% (분양잡과 디자인 톤 다름) |
| Cron / Webhook | 0% | 100% (분양잡엔 없음) |
| **전체** | **약 35%** | **약 65%** |

> 분양잡 단발성 결제 → 마피앱 정기결제 전환은 **로직 차이가 큼**. "코드 복붙" 보다는 "패턴 참조 후 재작성" 가깝게 진행.

## 8. 인프라 갭 (외주 작업 시작 전 도입 필요)

| 항목 | 현재 mapiapp 상태 | 작업 |
|---|---|---|
| **Prisma + DB** | 미설치 (`prisma/` 폴더 없음) | PostgreSQL 도입 + 본 v2 스키마 마이그레이션 |
| **NextAuth** | 미설치 | SNS 로그인 (Kakao/Google/Apple) 통합 |
| **Toss SDK** | 미설치 | `@tosspayments/payment-sdk` (클라) + 서버 fetch |
| **Cron 환경** | 미설정 | Vercel Cron 또는 자체 스케줄러 |
| **환경 변수** | 2개만 (`DATA_GO_KR_API_KEY`, `KAKAO_MAP`) | 결제 + DB + Auth 환경변수 추가 (§9) |
| **Webhook endpoint** | 없음 | `/api/billing/webhook` 신규 + Toss 콘솔 등록 |

> mapiapp은 현재 데이터 스크래핑/조회 위주로 구성. 결제·회원·DB 인프라는 **처음부터** 구축 필요.

## 11. 보안 / PCI 준수

- ✅ 카드 정보는 **Toss Payments에 전적으로 위임** — 우리 서버/DB에 카드번호/CVC 절대 저장 금지
- ✅ `billingKey`는 reference 토큰 (PCI 데이터 아님) — DB 저장 시 컬럼 암호화 권장 (PostgreSQL `pgcrypto`)
- ✅ Toss webhook 서명 검증 필수 (signature header 비교)
- ✅ HTTPS 전구간 (Vercel 기본)
- ✅ `TOSS_PAYMENTS_SECRET_KEY`는 서버에서만 사용, 클라 노출 절대 금지
- ✅ 사용자 입력 받는 결제 관련 필드는 모두 서버 검증 (amount/plan 클라 신뢰 X)

## 13. 외주 작업 완료 기준 (Acceptance Criteria)

### Functional

- [ ] 비로그인 → Free 자동 가입 → 매물 1건 등록 가능
- [ ] Free → Standard 전환 시 Toss billing 위젯 노출
- [ ] 카드 등록 성공 → billingKey 저장 + 첫 결제 즉시 실행
- [ ] 얼리버드 100명 정확히 카운팅 (race condition 방지)
- [ ] 매월 자동 charge cron 동작 (테스트 환경에서 짧은 주기로 검증)
- [ ] 결제 실패 시 D+1/D+3/D+7 재시도 + 알림
- [ ] 추가 등록(마피/일반/구인구직) 인앱 원클릭 결제 동작
- [ ] 추가 등록 매물 노출은 `exposureExpiresAt`까지 보장 (구독 만료와 무관)
- [ ] 해지 플로우 2-step 동작 (확인 다이얼로그 + 사유 설문)
- [ ] 자격증 인증 1개월 무료 적용 (admin 수동 승인)
- [ ] 환불 정책 (정기 7일 내 / 단건 미사용)
- [ ] webhook 서명 검증 + 결제 상태 동기화

### Quality

- [ ] 모바일 우선 디자인, 모든 CTA 44px 이상
- [ ] 디자인 토큰 (#2563EB, #F97316 등) 정확히 적용
- [ ] 회의록 v2 가격과 화면 표시 가격 100% 일치
- [ ] PaymentLog audit 모든 결제 이벤트에 기록
- [ ] 카드 정보 우리 DB에 미저장 (Toss 위임만)
- [ ] HTTPS + 환경변수 secret 보호
- [ ] 결제 화면 PWA/네이티브 호환 (iOS/Android 둘 다 정상)
